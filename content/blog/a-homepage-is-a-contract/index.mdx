The homepage is often treated as a table of contents with better lighting. That is too passive a description.

The first screen makes a contract with the visitor. It says what this person works on, what kind of attention the site rewards, and how much noise they will have to cross before reaching something real.

For this site, the contract is deliberately small. There is a name, a short introduction, a portrait, experience, projects, writing, and a few collections. Each section is a door. None of them should promise a room that does not exist.

## A count is a promise

The navigation cards show counts for projects, photos, writing, and books. A count looks like a small detail, but it changes how the page is read.

If the writing card says there are seven posts, the writing page needs seven posts. If the books card says six, the shelf should not quietly show four because two entries failed to load. The count is not decoration; it is a compressed statement about the data behind the page.

That is why the home view reads its public collections and published posts together. The section does not maintain a second hard-coded number. When an item is published in the owner panel, the public count can change with it.

The failure case is equally important. If the database is unavailable, the public query returns an empty-safe result. The interface becomes quieter, but it does not invent a count to preserve its shape.

## The fold needs a point of view

There is pressure to place everything above the fold: a large headline, a list of services, a row of logos, a call to action, and proof that the visitor is in the right place. That produces a page that introduces nothing because it is trying to explain everything at once.

The portrait gives this homepage its first visual pause. The introduction gives the visitor a sentence to hold. The rest can arrive after that. A portfolio does not need to behave like a landing page for a product with a conversion target.

This is also why the site keeps the content column narrow. The width is closer to a reading measure than a dashboard canvas. It lets the experience and project rows carry their own weight instead of turning every fact into a card.

## A section should earn its way back

The homepage links to the writing index, books, music, photos, and projects. Those links are useful only if the destination has a clear way back and remembers the same visual language.

The writing page groups posts by year. The book page turns records into a shelf. The project page keeps the repository data close to the project name. These are not separate microsites; they are different readings of the same person.

The back link on an article is small but important. A long post is a branch in the site, not a dead end. The visitor should not have to use the browser chrome to understand where they came from.

## The contract includes what is absent

There is no testimonial strip because there are no testimonials to publish. There is no “trusted by” row because a personal site should not borrow authority from anonymous marks. There is no stock desk photograph behind the introduction.

Absence can be a design decision when it keeps the page from making a claim it cannot support. The site can gain more sections later. For now, the better homepage is the one whose promises fit inside the data and the writing already there.

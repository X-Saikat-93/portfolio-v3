# Support

This repository is a personal portfolio rather than a product with a public
support team or response-time commitment. The documents below are the first
place to look before opening a request:

- [README](README.md) for setup, routes, scripts, and provider boundaries;
- [Operations](docs/operations.md) for environment and bootstrap work;
- [Architecture](docs/architecture.md) for module and trust boundaries;
- [Contributing](CONTRIBUTING.md) for change and verification expectations;
- [Security](SECURITY.md) for vulnerabilities or exposed secrets;
- [Code of Conduct](CODE_OF_CONDUCT.md) for participation concerns.

## Routing a request

- For a reproducible application defect, open an issue if repository issues are
  enabled. Include the affected route, expected behavior, actual behavior, a
  minimal reproduction, and the checks you ran.
- For a documentation or design correction, open a focused pull request or
  issue with the exact file and proposed change.
- For security concerns, use the private process in
  [`SECURITY.md`](SECURITY.md); do not publish exploit details.
- For private owner content, contact the owner privately through GitHub rather
  than placing the material in an issue or pull request.

Do not include credentials, private contact submissions, unpublished media, or
personal data in support requests.
